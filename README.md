# CricIntel — Fantasy Cricket Intelligence Dashboard

A single-page dashboard for IPL 2026: pick two teams (or tap a quick fixture) to get a win-probability read, pitch report, weather, a suggested Fantasy XI, a full squad points table, and a ready-to-record video script. Also includes Team Compare and Ground Report pages.

## 📊 How predictions work now

The win-probability model is grounded in **real IPL data**: `data.js` ships with the actual all-time head-to-head record between every pair of the 10 current franchises (all 45 matchups, matches/wins/losses through IPL 2025, sourced from public IPL records).

For any fixture:

```
win% = 65% × (team's real historical win rate vs this opponent)
      + 35% × (a seeded venue/form nudge, ±14 points)
```

So MI vs KKR (a real 22–10 MI-favoured record) will consistently lean toward MI, CSK vs RCB will lean CSK, evenly-matched pairs like MI vs RR (13–13) will sit close to 50/50 — and the venue nudge still gives some game-to-game variation instead of the same number every time. The **Head to Head** card on the dashboard now shows the real all-time record and count, not a random one.

**What's still simulated:** player names, individual fantasy points, credits, and the exact weather/pitch numbers are generated by a seeded algorithm in `data.js` (same matchup + venue always gives the same result) — there's no live squad/player-stats feed wired in yet. See "Going further" below for how to replace that.

## 🔴 Optional: live data (free API)

`api.js` adds an **optional, free** live-score layer on top of the historical model:

1. Sign up free at **https://cricketdata.org/member.aspx** (CricAPI / Cricket Data — 100 requests/day on the free tier, no credit card).
2. Copy your API key.
3. Open `api.js` and paste it into `CRICAPI_KEY = ''`.
4. Reload the page. When you analyze a fixture that's actually live or scheduled today, a 🔴 **LIVE DATA** banner appears on the Match Winner card pulling the real match name/status from the API.

Leave `CRICAPI_KEY` blank and the app runs exactly as before — fully offline, no API calls, no errors. The app checks `CricLive.enabled()` before ever calling out to the network.

**Publishing note:** this is a static site, so a pasted API key is visible in the page source to anyone who looks. That's an acceptable tradeoff for a free-tier, rate-limited hobby key — just don't paste a paid/production key into a public GitHub repo. If you need to hide it, put the fetch behind a small serverless function (Vercel/Cloudflare Workers/Netlify Functions all have free tiers) instead of calling CricAPI directly from the browser.

## Going further

To make the *player-level* data (Fantasy XI, squad points, credits) real instead of simulated, replace `makeSquad()` and the fantasy-points logic in `data.js` with a call to a real stats/fantasy API — for example CricAPI's `fantasySquad` endpoint, or a paid provider like EntitySport/Highlightly if you need deeper ball-by-ball stats. Every render function in `app.js` already reads from the same data shape (`{name, role, team, teamColor, pts, credits}`), so nothing else needs to change — just swap what populates `fullSquad` and `fantasyXI`.

## Troubleshooting: "the page loaded but the team picker is empty/greyed out"

This is almost always a **stale cache** — your browser (or GitHub's CDN) is still serving an old `app.js`/`data.js` from before your latest push, while `index.html` is the new version. A mismatched pair can throw a JS error on load and leave the whole page blank.

Fixes, in order:
1. Hard-refresh the page: **Ctrl+Shift+R** (Windows/Linux) or **Cmd+Shift+R** (Mac).
2. Open DevTools (F12) → Console tab → look for a red error. It'll say exactly which file/line failed.
3. `index.html` loads the scripts with a `?v=2` cache-busting query string (`data.js?v=2`, etc.). Whenever you edit `data.js`, `api.js`, or `app.js` and push again, **bump that number** (`?v=3`, `?v=4`, ...) so browsers are forced to fetch the new file instead of a cached one.
4. Give GitHub Pages a minute or two after pushing — it serves through a CDN that takes a short time to pick up new commits.

`app.js` is also written defensively now: if one element is missing or renamed, it logs a warning to the console and keeps going instead of crashing the entire page.

## Files

- `index.html` — markup + styles
- `data.js` — team/venue data, real IPL head-to-head history, and the seeded analysis generator
- `api.js` — optional free live-data layer (CricAPI) — safe to leave untouched
- `app.js` — all interactivity (page nav, team picking, rendering, Compare, Ground, live banner)

## Run locally

Just open `index.html` in a browser — no build step, no dependencies.

## Publish with GitHub Pages

1. Create a new GitHub repo and push these files (`index.html`, `data.js`, `api.js`, `app.js`, this README) to it.
2. In the repo, go to **Settings → Pages**.
3. Under **Build and deployment**, set **Source** to `Deploy from a branch`, branch `main`, folder `/ (root)`.
4. Save — GitHub gives you a live URL (usually `https://<username>.github.io/<repo-name>/`) within a minute or two.
